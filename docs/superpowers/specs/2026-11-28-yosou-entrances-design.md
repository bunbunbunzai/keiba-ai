# 「予想」を探す人の入口を作る（競馬場ページ・G1の事前評価・WIN5）設計メモ（2026-11-28）

## 目的と理由
人数の目標は2027年3月末（数え方は持ち主に確認中：3月末までの累計1万人か、月1万人か）。11/27時点で累計580人、直近7日は1日29人。
流入の62%はBingとChatGPTで、入口は「過去の結果一覧」と「特集まとめ」（上位6ページで半分）。来ているのは「いつ・過去の結果」を調べる人で、「予想」を探す人の入口が無い。
Bingの検索結果を見ると（11/28未明）、次の3つの言葉では、全頭ログと同じ材料を持つ小さなサイトが1ページ目にいて、全頭ログは出ていない。

- 「大井競馬 予想」「園田競馬 予想」「佐賀競馬 予想」「高知競馬 予想 今日」：競馬場ごとに「今日・次回開催のAI予想」のページを持つサイト（高知は1位）
- 「チャンピオンズカップ 予想」「ジャパンカップ 予想」「有馬記念 AI予想」：登録馬の段階から「予想」のページを出しているサイト（「登録馬19頭と過去10年データ」など）と、noteの記事
- 「WIN5 予想」「WIN5 AI予想 今週」：「今週のWIN5予想」を1ページで毎週入れ替えているサイト

全頭ログは全レースの予想を毎日出しているが、競馬場ページは成績とガイドのページで、G1の予想が出るのは金曜、WIN5のページは無い。
そこで、いまある予想を「探されている言葉の入口」に載せる。G1の日程に左右されない入口（地方は毎日、WIN5は毎週）を作るのがねらい。

## やること（持ち主が選んだ「案1」。この順に進める）
1. **競馬場ページ（/venue/<場>/）を「今日・次回開催のAI予想」の入口にする**
2. **G1の「事前評価」（登録馬の段階のAIの評価）を、枠順が出る前から重賞ページに出す**
3. **WIN5のページ（/win5/）を作り、対象レースの予想を前日の夜に出す**

（案1のうち「GitHubのREADMEにサイトへのリンク」は、別のプルリクエスト #9 で出した。）

## やらないこと
- 予想の評価の決まり・買い目・成績の計算を変えること。事前評価とWIN5の記録は成績（results_ledger）に数えない。
- 地方のレースの予想を、前の晩に全部出すこと（下の「自分で決めた点」2）。
- G2・G3や地方の重賞の事前評価。
- WIN5の買い目のおすすめと、払戻金の記録。
- 新しいページを増やすこと。増えるのは /win5/ の1ページだけ（サイトは487MBで、GitHub Pages の上限1GBに向けて毎日増えている。Googleに載せるページを絞る方針もある）。

## 避けること
- 事前評価を、確定した予想と取り違えさせること。
- 予想がまだ出ていないレースを、出ているように見せること。
- データに無い数字をAIが書くこと（数字は与えたものだけ。重賞の全頭診断記事と同じ決まり）。
- 「今日」「明日」のように、作った時刻でずれる言葉を固定の文に書くこと（サイトは作り置きで、次に作り直すまで文が変わらない）。
- 対象レースや締め切り時刻の誤り（JRAの発表から機械的に取り、変わることがあると書く）。
- 1ページに同じPRを2つ出すこと。

- **(a) いまの競馬場ページの上に「次の開催日の全レース」を置き、題名と見出しを「〇〇競馬 予想＋日付」にする（採用）**：URLが変わらない。レースページのパンくず（トップ › 日付 › 競馬場 › R）から、すべてのレースページがすでにリンクしている。ページは増えない。

### 2. G1の事前評価
だれが評価するか：
- **(a) 毎日の取得（entries.yml。12:17）の中で Anthropic API を呼ぶ（採用）**：登録馬・出走予定馬・馬ページの取得と同じ流れで、全自動。重賞の全頭診断記事（scraper/article_gen.py）と同じ形にできる（表はプログラム、評価と短評だけAI）。呼ぶのは1レースにつき1〜3回。鍵（ANTHROPIC_API_KEY）が無い・切れている間は何もしない。

- (c) AIを使わず、レーティングと近走の着順から機械的に並べる：安定するが「AIの評価」と言えず、短評が出せない。

どこに出すか：
- **(a) 重賞ページ（/graded/<レース>/）に載せ、特集まとめからは1行で案内する（採用）**：重賞ページは題名にすでに「AI予想」が入っていて、毎年同じURLに積み上がる。特集まとめは「いつ・日程」の言葉で上位にいるので、題名を変えない。
- (b) 特集まとめの題名を「AI予想」に変える：いま効いている「いつ」の検索を失うおそれがある。
- (c) 全頭診断の記事（/column/<レース>-<年>/）を月曜から出す：記事は予想ファイルから作る仕組みで、作り直しが大きい。

- (b) 開催日ごとにページを作る：ページが増える。

## 決めたこと

### 1. 競馬場ページ
- **対象**：競馬場ページの全部（地方15場・中央10場。site/build.py の venue_pages）。
- **「次の開催日」の決め方**：サイトを作った時刻（日本時間）から見て、その場にまだ発走していないレースがある、いちばん近い日。出馬表（data/races/<日付>/）から決める（予想がまだ無くても、出馬表があれば対象）。無ければ、今日の開催（結果つき）。それも無ければ、いまの形（最近の予想）のまま。
- **並べる順**：パンくず → 見出し → 冒頭の1〜2文 → **次の開催日の全レース** → 成績の数字 → 楽天競馬のPR（地方だけ。いまと同じ1つ） → よくある質問 → 競馬場ガイド → 最近の予想（直近3開催日） → 当日バイアスの履歴 → 過去の開催日。
- **次の開催日の全レース**：発走時刻の順。予想があるレースは、いまの一覧と同じ形（◎・自信度・オッズ・結果。レースページへのリンク）。予想が無いレースは、発走時刻・条件と「予想は〇〇ごろ公開」（リンクなし）。
- **「予想は〇〇ごろ公開」の決まり**（PREDICT.md の回に合わせる。目安として書く）：13時より前に発走するレースと、重賞・WIN5の対象レース＝前日の21時ごろ。それ以外＝当日の12時30分ごろ。
- **冒頭の文**：開催日（月日と曜日）、レース数、第1レースと最終レースの発走時刻、予想を公開済みのレース数。出馬表にあることだけを書く。続けて、いまの成績の文。
- **題名**：「{場}競馬 予想｜{M月D日}（{曜}）全{n}レースのAI予想【今日・次回開催】｜競馬全頭ログ」。見出しは「{場}競馬のAI予想（{M月D日}・全{n}レース）」。説明文にも日付・レース数・第1レースの発走時刻を入れる。次の開催日が無いときは、いまの題名のまま。
- **よくある質問**（特集まとめと同じ形。質問と答えの形式〈FAQPage〉も入れる）：(1) {場}競馬は{M月D日}何時から？（第1レース・最終レースの発走時刻） (2) AI予想はいつ出る？（上の決まり） (3) AI予想の成績は？（その場のレース数・回収率・◎の3着内率） (4) 馬券はどこで買える？（site/hubfaq.py にある確かめ済みの文面を使える範囲で。使えなければ省く）
- **「今日」「明日」**：固定の文には日付だけを書く。題名の「今日・次回開催」は、どの時刻でも外れない言い方として入れる。
- **検索エンジンへの知らせ**（IndexNow）：競馬場ページの状態を「次の開催日＋予想済みのレース数」にして、開催日が替わったときと予想が増えたときに知らせる（1日に2〜3回まで）。サイトマップの更新日は作った日。
- **内部リンク**：競馬場の一覧（/venue/）で、次の開催日がある場を上に並べ、日付を添える。トップの当日の一覧から各場のページへのリンクを1か所。
- **計測**：GA4 の入口ページ（/venue/…）と、Bing の /venue/… の表示・クリック、「〇〇競馬 予想」の言葉。公開の2週間後に確認する。

### 2. G1の事前評価
- **対象**：14日以内に行われるJRAのG1（障害のJ・G1を含む。日程は data/graded_hist/<年>.json）で、馬の一覧（data/entries の出走予定馬。無ければ data/nominations の特別登録馬）があり、その日の予想（predictions）がまだ無いレース。
- **作る場所**：scraper/pre_eval.py（新しく作る）。entries.yml の「馬ページ」の手順のあとで実行し、data/pre_eval/<レースの名前>-<開催日>.json に保存する（保存の対象に data/pre_eval を足す）。レースの名前（slug）は、site/weekly.py の特別登録馬の読み込みと同じ決め方（extra.graded_slug）。
- **AIに渡すもの**（1レースを1回の呼び出しで）：レースの条件（名前・日付・場・コース）と、馬ごとの性齢・調教師・JRAのレーティング（出ていれば）・通算成績・直近5走（日付・場・レース名・芝ダート・距離・頭数・人気・着順・騎手）。出どころは data/entries・data/nominations・data/horse_info だけ。
- **AIに頼むこと**：PREDICT.md の5つの軸（能力・人的・条件適性・展開利・状態）を1〜5点で付ける。枠順・騎手・馬体重が出ていないので、材料の無い軸は3点（PREDICT.md の「データ不足の軸は3点」）。あわせて、上位6頭ほどの想定勝率、1頭ずつの短評（40字前後）、全体の見立て（2〜3文）、暫定の印（◎〇▲△）。返すのはJSONだけ。数字は与えたものだけ、馬名は与えた表記のまま。モデルは scraper/ai.py の "analysis"。
- **評価点**：軸の点に重み（4・2・1・1・1）を掛けて足す計算は、プログラムでやる（45点満点）。
- **検算**（通らなければ保存しない。前の版があれば残る）：馬の一覧が渡したものと一致／点が1〜5／想定勝率の合計が100以下／印が一覧の馬／短評に、その馬の材料とレースの条件に無い数字が入っていない（入っていたら、その短評だけ落とす）。
- **作り直すとき**：馬の一覧・レーティング・直近の出走が変わったとき（渡す材料が同じなら呼ばない）。1レースにつき1日1回まで。
- **鍵が無い・失敗したとき**：何もしない。続けて3回失敗したら打ち切る（ai.py の決まり）。
- **見せ方**（site/weekly.py に「事前評価」の節を足す）：
  - 重賞ページ：「次に見る」のあと、JRAの馬の表の前に「{レース名}{年} AIの事前評価（{M月D日}時点・登録馬{n}頭）」。全体の見立て → 表（暫定の印・馬名・評価点・想定勝率・短評。評価点の高い順） → 注意書き「枠順・騎手・オッズが出る前の評価で、成績には数えない。出走しない馬が含まれることがある。確定版のAI予想（印と買い目）は{公開の予定}」。
  - 重賞ページの題名（予想がまだで、事前評価があるとき）：「{レース名}{年} AI予想｜登録馬{n}頭の事前評価と過去20年の傾向」（出走予定馬の発表後は「出走予定馬{n}頭の事前評価」）。説明文に、暫定の上位3頭の名前。
  - 確定版の予想が出たら：題名はいまの「【AI予想】…全頭診断と買い目」になり、事前評価の表は出さない。「{M月D日}時点の事前評価では◎{馬名}だった」の1行だけ残す。結果が出たあとも消さない（全部記録する方針）。
  - 特集まとめ：冒頭の箱に「AIの事前評価を見る」の入口を1つ足す。題名と説明文は変えない。「よくある質問」の「AI予想はいつ出る？」に、事前評価を公開中であることを足す。
  - X・Threads への投稿はしない。馬のページは触らない。
- **更新日**：重賞ページの更新日に、事前評価を作った日を入れる（検索エンジンへの知らせもそれに従う）。
- **計測**：Bing の /graded/<レース>/ の表示・クリックと、「{レース名} 予想」「AI予想」の言葉。チャンピオンズC（12/6）→ 阪神JF（12/13）→ 朝日杯FS（12/20）→ 有馬記念（12/27）の順に見る。

  - 次の開催日の対象がまだJRAに出ていないときは、直近の開催日の結果と「次回の対象レースはJRAの発表後に掲載」。
- **リンク**：フッター、今週末の競馬まとめ（/weekend/）、用語集のWIN5、トップ（中央の開催がある日だけ）から1か所ずつ。ヘッダーの6項目は変えない。対象レースのレースページに「WIN5の{n}レース目」の札と /win5/ へのリンク。
