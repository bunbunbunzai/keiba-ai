# Threads への自動投稿（2026-11-25）

## 目的
X・Instagram 以外からの流入と認知を増やす（2027年3月末 10,000UU の上乗せ）。Threads は国内の利用が伸びており、文字だけの会話型の投稿が中心なので、画像なし・問いかけ型で出す。

## やること・やらないこと
- やること：今の自動投稿（scraper/social.py・social.yml）に、3つ目の投稿先として Threads を足す。
- やらないこと：画像つき投稿、返信への自動応答、インサイトの取得。必要になったら別に足す。
- 避けること：機械的な連投でスパム扱いされ、アカウントを止められること（Instagram は API 接続を止められた経緯がある）。

## 検討した作り方
1. **今の social.py に足す（採用）**：候補の選び方・状態の記録・6時間で古い下書きを捨てる仕組みをそのまま使える。変更が小さい。
2. 別のスクリプト・別のワークフローにする：独立はするが、候補の判定と状態の記録を二重に持つことになる。
3. 外部の予約投稿サービスを使う：月額がかかり、鍵を外に預けることになる。

## 決めたこと
- 出す投稿：重賞の予想（前日夜。前日に出したレースは当日に重ねて出さない）・重賞の結果・昼の厳選レース・夜の全成績・大きな的中。
- 重賞は中央の重賞と G1（Jpn1 を含む）だけ（`threads_scope: "jra"`）。地方の重賞は毎日あり件数が増えすぎる。
- 1日の上限は `threads_max_per_day`（全成績は数えない）。開設直後は 1 で始め、2週間ほど様子を見て 3 に上げる。
- 文面は X の流用ではなく問いかけ型。言い回しは数種類を投稿ごとに変える。タグは1つ。500字以内。
- リンクは重賞の予想・結果と全成績だけに付ける（`threads_link_kinds`）。
- 続けて3回失敗したら送るのをやめる（`social/status.json` の `threads_fail_streak` を消すと再開）。
- 鍵は GitHub Secrets の `THREADS_ACCESS_TOKEN`（60日で切れる）。`GH_SECRETS_PAT`（Secrets を書ける鍵）を登録すれば週1回自動で延長する。無ければ60日以内に開発者サイトで作り直す。
- Meta 側のアプリは「競馬全頭ログ投稿」（ID 2944148212634315）。止められた旧アプリ・ビジネスとは切り離してある。

## 確かめ方
`python tests/test_social_threads.py`（出す・出さないの決まり、文面、上限、停止）。本番は `social.yml` を手動で動かし、`--only` で1件だけ出して確かめる。
